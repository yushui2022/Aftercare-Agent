# ADR-0011：模型 provider 暂不绑定具体模型

状态：接受；适用于当前 Aftercare 开源版 v0.1 和真实部署路线。

## 决策

Aftercare 保留 provider-neutral 的模型接缝，但不把 JEV 或任何单一模型加入业务主线。当前产品路线先完成业务状态、证据账本、EGM 调查接入、人工协作、Action Ledger、连接器契约和部署验收。模型只作为可替换的语义建议 provider，不能拥有数据库连接、EGM 写权限、业务审批权或外部动作权限。

JEV 的实验适配器不属于 EGM 核心，也不属于 Aftercare 运行时。已有实验结果保留在实验环境中作为历史资料；实验代码和模型凭据不进入发布包、默认 Compose 或生产部署。

## 原因

当前测试证明的是特定 JEV 请求协议与售后路由标签之间存在不稳定，不足以支持把它接入关键路径。与此同时，订单状态、证据新鲜度、撤回、幂等、租约、审批和外部动作等问题，首先需要确定性业务契约和可恢复运行时解决。过早绑定一个模型会把模型表现、业务规则和证据准入混在一起，使故障难以定位，也会限制后续更换 provider。

## 运行边界

- 代码负责明确规则、状态转换、权限、幂等、预算和降级。
- EGM 负责受控证据准入、事实依赖、失效传播和可追溯上下文。
- 模型负责有限的语义提取或建议，例如客户意图、材料分类、需要补查的方向。
- 人工或业务策略决定高风险动作；模型输出不能直接授权退款、补发、发信或关闭案件。

## 重新评估条件

只有在以下条件都满足时，才重新比较 JEV 或其他模型：

1. 订单、物流、买方陈述的调查 EGM schema 已固定并有 PostgreSQL 恢复与隔离验证；
2. 业务 Harness 已冻结，问题被拆成可单独标注的语义判断，而不是一个宽泛的最终路由；
3. 有确定性规则、人工参考和至少一个替代 provider 的对照；
4. 以误放行、漏升级、误升级、延迟和成本作为指标，且结果按案例类别报告；
5. shadow 结果连续稳定，模型故障时能自动降级到确定性路径或人工队列。

## 后果

短期内不会得到一个“开箱即用的模型售后 Agent”，但业务内核和部署路径不会被某个模型的早期表现绑住。后续换模型时，只需实现同一 provider 契约并重新通过 Harness、权限、故障和成本验收。
